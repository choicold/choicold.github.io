## Problem & Solution

**Problem**: 마스터 DB에 없는 식재료는 등록할 수 없어, 미등록 식재료의 소비기한을 제공하는 LLM 자동화 파이프라인 도입 검토

**Solution**: 온라인몰 상품 450개와 마스터 DB를 비교하고 미포함 상품을 분석해 자동화 도입 보류. 사용자 커스텀 등록과 관리자 검토를 통한 마스터 DB 보완 방안 선택

## Core Features

- **식재료 관리**: 냉장고 속 식재료의 소비기한과 재고 관리
- **레시피 추천**: 보유 식재료를 활용한 AI 맞춤 레시피 추천
- **식재료 마스터 DB**: 약 36만 개 레시피의 식재료명을 바탕으로 611개 품목 설계
- **배포 자동화**: AWS EC2와 RDS 기반 서버 배포 및 GitHub Actions 파이프라인 구축

## Technical Highlights

- **판단 기준**: 핵심은 보유 식재료로 요리할 레시피를 추천하는 것. 소비기한 자동화에 비용을 들이기 전에 미등록 식재료의 규모부터 확인
- **표본 선정**: 1인 가구의 온라인 구매를 가설로, 상품 분류가 갖춰진 컬리와 SSG에서 450개 상품을 수집해 마스터 DB와 비교
- **분석 결과**: 커버리지 **82% 확인**. 미포함 약 18%는 밀키트와 완제품 등으로, 핵심 대상인 요리용 식재료의 누락은 적다고 판단
- **해결책 선택**: **LLM 자동화 도입 보류**. 예외는 커스텀 등록으로 수용하고, 마스터 DB 반영은 관리자가 검토하는 방안 선택
- **판단의 한계**: 상품 표본의 포함 비율로 실제 요청량을 확정할 수는 없음. 운영 중 등록량과 검토 부담에 따라 자동화 재검토 필요

## Impact

- 상품 450개에서 <strong>마스터 DB 커버리지 82%</strong>를 확인하고 미포함 상품의 성격을 분석해, 소비기한 자동화의 도입 우선순위 판단
- 미등록 식재료를 수용할 **커스텀 등록과 관리자 검토 방안 설계**. API 비용 절감액과 운영 효과는 별도로 측정하지 않음
